# Reroute component evaluation v0.1

## Scope and identity

This diagnostic run isolates the production `CapabilityGapDecider` from Main
Agent candidate selection. It does not change RerouteController semantics,
RuntimeEvidence, CapabilityMemory, Bundle behavior, Retrieval Cards, BM25,
Dense, RRF, provider configuration, or benchmark gold.

- Exact implementation HEAD: `1b7d77393697718867e3a8f9a45ea539d3ca0ea3`
- Branch: `feature/reroute-controller-v0.1`
- Provider/model: BigModel / `GLM-5.3-flash`
- Corpus/retrieval: frozen S128 / BM25 + Dense + RRF
- Repeats: one scored call per case
- Gap cases: 12 frozen, 11 production-ingress eligible and scored
- Selection cases: 11 frozen and scored
- Gap case SHA-256: `0222fc2dea41bd57c1d63958b3673f61d1b96b9c6ec75929c4a2d239db0a4076`
- Selection case SHA-256: `54986b53f153a57226f295c8ffc0074074ddc70dcd257aee13ed3986ac2a1f3c`

The GapDecider run used `CompletionCapabilityGapDecider` unchanged. Each case
entered through `RerouteController.observe()`. A predicted gap caused the
controller itself to call the current production discovery implementation; the
secondary retrieval observations are therefore downstream of the model's
generated need rather than gold queries.

The selector run did not add a production selector abstraction. It presented
the Main Agent with current synthetic evidence, generated-style need, active
Bundle Cards, frozen candidate Skill IDs, compact Retrieval Cards, and ranks.
Action was optional and not scored.

## Diagnosis

The remaining bottleneck in this frozen sample is closest to **C. candidate
selection**. Gap classification made no scored errors, generated needs recovered
every positive target in top 5, and every selector gold target was present in
the frozen candidate sets. Selection nevertheless produced one missing required
Skill and three wrong selections. The sample is intentionally small and
one-repeat; it does not justify production tuning or a general claim that gap
classification and retrieval are solved.
